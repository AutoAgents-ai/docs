<Update label="9月4日 - 9月18日" tags={["v2.1.0.0"]} rss={{ title: "Agentify v2.1.0.0", description: "Agent 並列実行とテストケース集、Text2Agent 自動デバッグを強化。モデル状態の可視化と Skill ファイル添付を拡充し、データダッシュボード統計・ナレッジベース引用バッジ・一括モデル置換などを追加。19 件の不具合を修正" }}>
  ## 一、バージョン概要

  本バージョンでは、Agent の並列実行とテストケース集、Text2Agent の自動デバッグ能力を重点的に強化しました。モデル状態の可視化ガバナンスと Skill のファイル / 添付拡張を整備し、データダッシュボード統計、ナレッジベース引用バッジ、オーケストレーションでの一括モデル置換などの強化も実施しています。あわせて 19 件の不具合を修正し、複数のシステム最適化を完了しました。

  ## 二、コア変更

  ### 2.1 Agent - 並列実行エンジン

  Agent オーケストレーションに**並列実行**能力を追加し、直列モードとの互換を保ちつつ大幅に効率化します：

  - Agent は**直列 / 並列**の両実行モードに対応。**既存データはデフォルトで直列**のまま、新しい並列能力はスイッチで有効化
  - **並列度**を設定可能（単一 Agent 最大 16、システム全体上限 1000 は設定可能）
  - 並列スケジューリングは**直列 + 並列のデュアルキュー**戦略を採用：
    - **直列**：`発話` ノード、中断可能ノード、メモリ書き込みノード
    - **並列**：一般処理ノード
  - **サブ Agent、for ループ**などのネストシナリオでも並列実行に対応

  ### 2.2 テストケースと自動デバッグ

  - Agent の**コンポーネントデバッグ**と**試実行**の両方で**テストケース集**の追加に対応
  - **Text2Agent 自動デバッグ**に対応し、Agent オーケストレーションと検証の効率を向上

  ### 2.3 モデル状態の可視化

  モデル管理に**状態検知とアラート**能力を追加：

  - モデルの可用性と応答速度を定期検知
  - Agent オーケストレーション、コードブロック IDE、Skill、アプリなど**すべてのモデル選択入口**で、**赤 / 黄 / 緑**の状態によりモデル健全性を提示
  - 利用側は追加調査なしでモデルの可用性を把握可能

  ### 2.4 Skill ファイルと添付

  - Skill が **Binary ファイル保存**に対応（画像、Word、PPTX、PDF など一般的な形式）
  - **Text2Skill** がファイル・画像などの添付を参考資料としてアップロード可能
  - Skill が扱える資料タイプと利用シーンをさらに拡充

  ### 2.5 ナレッジベース引用バッジ

  Agent コンポーネントにナレッジベースを追加した後：

  - 検索内容の**引用バッジ**を表示可能
  - 推論中にナレッジベースツールコンポーネントを呼び出す場合も、**バッジ生成と引用元の確認**に対応

  ### 2.6 データダッシュボード統計

  モデル呼び出し統計の集計表を 2 つ追加：

  - **Agent** モデル呼び出し統計集計
  - **アプリ** モデル呼び出し統計集計

  アプリのモデル請求とチャット記録に **`app_id`** フィールドを追加し、ダッシュボードの照会ロジックと性能を向上。

  ### 2.7 オーケストレーションとテンプレート能力

  - オーケストレーション画面で**一括モデル置換**に対応
  - インテリジェントノードのバックエンド既定 **max_token** を **32000** に調整（インテリジェント対話 / Agent ノード、ドキュメント質問ノード、画像質問ノード。従来の既定 3000 は過小）
  - Agent コンポーネントから「最大反復回数」パラメータ欄を削除し、バックエンド既定は **200**（設定可能）
  - **Excel コンポーネント**の生成テンプレート構文を最適化：
    - 変数入力が配列の場合、自動的に `{"list": []}` でラップ
    - `for` / `hfor` ループが**中国語変数名**に対応
  - テンプレート関数が**参照変数**による引数渡しに対応。例：`[@["functionName", "*{{args1}}", "*{{args2}}", ...]@]`
  - **`KbMerge`** 関数を追加：複数のナレッジベース照会結果を結合して TopK を取得

  ## 三、その他の更新

  - **システム管理**：ユーザー管理で**システム内蔵アカウントを非表示にするか**を設定可能にし、一部顧客の非自然人アカウント管理要件に対応。組織構造ページの組織ツリー領域は**ドラッグでサイズ調整**に対応
  - **ファイルとストレージ**：ファイルストレージの**瞬間転送**で履歴ファイルが削除済みかを検出可能に。ファイルアップロードは**直接ディスク書き込み**し、全内容をメモリへ読み込まない。**OFD** 拡張ファイル対応を追加し、**中国語フォント**適応を完了
  - **運用監視**：サービスの**ヘルスチェック**と簡易**監視 API** を提供し、バックエンドのシステムリソース情報を確認可能。プローブと監視の統合を容易に
  - **パフォーマンス最適化**：Token 消費統計の定時タスクを最適化して MongoDB 負荷を低減。ナレッジベースチャンクの MongoDB インデックスを最適化

  ## 四、体験変更

  以下の変更は、既存の UI 表示、既定値、または操作導線に影響します：

  - **Agent 並列**：新しいオーケストレーションでは並列モードを有効化可能。**既存 Agent はデフォルトで直列**のまま、並列スイッチを手動で有効化する必要あり
  - **max_token 既定値**：インテリジェント対話 / Agent / ドキュメント質問 / 画像質問ノードの既定を 3000 から **32000** に変更
  - **最大反復回数**：Agent コンポーネントのフロントから当該フィールドを非表示。バックエンド既定 200（設定可能）
  - **モデル選択**：各モデル選択入口に赤 / 黄 / 緑の状態表示を追加
  - **オーケストレーション画面**：一括モデル置換の入口を追加
  - **キーワード認識コンポーネント**：デバッグ / テストケース Tab を削除。ドキュメント審査を有効化した後、デバッグ画面のアップロード入口と操作を同期調整

  ## 五、不具合修正

  ### 5.1 Agent 関連

  - 並列実行中に**ユーザー質問**が発生するとプロセスが直接中断される問題を修正
  - **サブ Agent 並列**時に出力が乱れる問題を修正
  - 並列 + サブ Agent シナリオで、**親 Agent の再実行**が親 Agent から開始されない問題を修正
  - サブ Agent が並列であるべきなのに**実際は直列**実行される問題を修正
  - オーケストレーション画面を**左右ドラッグで完全に折りたたんだ**後、コンポーネントをクリックできない問題を修正
  - Agent の**情報分類**コンポーネントデバッグ機能のエラーを修正
  - Agent の**情報抽出**コンポーネントデバッグ機能のエラーを修正
  - **PPT 生成**コンポーネントのエラーを修正
  - **ドキュメント質問**で TXT、OFD ファイルをアップロードするとエラーになる問題を修正
  - Agent の**拡張質問**がモデル空でも空実行してエラーになる問題を修正
  - Python コードブロックで偶発的にサードパーティライブラリの読み込みに失敗（`patchelf` 読み込み失敗）し、後続コード呼び出しが失敗する問題を修正

  ### 5.2 ナレッジベースと Skill

  - ナレッジベースの **PPTX ファイル解析**が無応答になる問題を修正
  - **Text2Skill** の翻訳が表示されない問題を修正
  - **Text2Skill @ ファイル**機能が有効にならない問題を修正

  ### 5.3 アプリと UI

  - アプリモジュールの一部領域で**文字をコピーできない**問題を改善（ブラウザ互換性）
  - アプリのエラー提示文言を**中国語**に調整
  - **動画タイプファイル**の icon 破損を修正
  - **ドキュメント審査**スイッチ有効化後、デバッグ画面にドキュメントアップロード入口がない問題を修正

  ### 5.4 データダッシュボード

  - モデル分析関連指標に表示される**モデル名が正しくない**問題を修正
</Update>

  ## バージョン概要

  本バージョンでは、発見ページ体験とリソースお気に入り機能を重点的に強化し、権限・申請体系を整備しました。スマート端末のテレメトリと OTA 管理能力をアップグレードし、ファイルストレージサービスの独立化改造と小モデル連携拡張を完了しています。あわせて 11 件の不具合を修正しました。

  ## コア変更

  ### 一、発見ページ体験のアップグレード

  - プラットフォーム入場時のデフォルト遷移先を発見ページに変更。発見権限がない場合は、権限のある最初のメニューへ自動遷移します。
  - 発見カードの情報をより充実：
    - 作成者と購読数を表示
    - 申請型 Agent はカード上で「購読済み」「購読中」「未購読」の状態を区別
    - 「審査不要」フィールドを「申請不要」に統一。申請フローが必要な Agent には「申請必要」を表示
    - 申請不要フローではフロントエンドのフォームを廃止し、会社・部門・時間・申請者をバックエンドで自動記録
  - 発見ページのスタイルも合わせて最適化。

  ### 二、7 大リソースのお気に入りと Agent フィルタ

  - Agent、アプリ、スキル、ナレッジベース、MCP、データベース、カスタムツールの 7 リソース種別でお気に入りに対応。
  - Agent の作成・購読・認可画面にカテゴリフィルタを追加し、作成時間 / 更新時間での並べ替えにも対応。

  ### 三、権限と評価機能の強化

  - 辞書に利用権限の割り当て機能を追加し、読 / 書 / 管の権限制御を補完。
  - 評価機能の権限を細粒度で調整し、フロントエンドの操作も同期して最適化。

  ### 四、スマート端末能力のアップグレード

  - **テレメトリ API サービスを公開**し、以下に対応：
    - 起動記録
    - 呼び出しログ
    - 呼び出しチェーン
    - クラッシュログ
    - 会話記録
  - **OTA 管理ページの最適化**：バージョン連番を削除し、アプリコードを追加。複数アプリの独立したバージョン管理と公開に対応。

  ### 五、モデルとナレッジベース能力の拡張

  - モデル管理で小モデル方式の連携に対応し、OCR、ASR、ドキュメント解析などのシナリオをカバー。
  - ナレッジベースファイルの外部プレビュー表示に対応し、機能拡張の連携を完了。

  ### 六、ファイルストレージサービスの独立化改造

  - ファイルストレージサービスを独立化し、ファイル IO 負荷をメインサービスから分離。全体の安定性とスループットを向上。
  - Aliyun OSS ストレージで指定ルートパス配下への保存に対応。

  ## その他の更新

  - **システム設定**：Agent 種別の「人気おすすめ」を「すべて」に変更。
  - **申請フォーム**：申請送信フォームの必須項目を上方へ移動し、入力しやすく改善。
  - **操作マニュアル**：操作マニュアルへの入口リンクを追加。
  - **コードブロック**：`networkx` 依存パッケージを追加。
  - **メッセージキュー**：RocketMQ で One SDK 方式の呼び出しに対応。
  - **API 調整**：一部ページで `/bill/listAllUsers` を廃止し、`user/suggest` に統一。
  - **国際化**：上記関連機能の国際化を同期完了。

  - **スマート端末 OTA**：バージョン連番を削除し、アプリコード単位で複数アプリのバージョンを管理。
  - **セルフサービスモード**：購読数を表示しない。「自分に認可」の 7 種別リソースは作成者を統一表示。

  - センシティブワード辞書にデータがない状態でページを更新すると、初回の追加ダイアログが固着して閉じられない問題を修正。
  - センシティブワードコンポーネントの辞書一覧に「自分に認可」辞書が表示されない問題を修正。

<Update label="8月7日 - 8月21日" tags={["v2.0.9.0"]} rss={{ title: "Agentify v2.0.9.0", description: "リソース権限体系を再構築し、AutoGUI に自動プリコンパイル修正を追加。大量データ時の読み込みと並行処理を最適化し、23 件の不具合を修正" }}>
  ## バージョン概要

  本バージョンではリソース権限体系を再構築し、AutoGUI に自動プリコンパイル修正機能を追加しました。また、大量データシナリオでの読み込みと並行処理を最適化し、23 件の不具合を修正しています。

  ## コア変更

  ### 一、リソース権限体系のアップグレード

  - 権限の粒度を「特定リソース種別へアクセスできるかどうか」から、リソースとアクションの 2 次元へ細分化しました。
  - **対象リソース種別**：MCP、アプリ、Skill、カスタムツール、データベース、モデル。
  - **統一アクションモデル**：読 / 書 / 審 / 管。全リソース種別で意味を統一。
  - **データ管理モジュールの権限能力を同時に補完**：
    - 権限に応じたデータの削除・編集制御に対応
    - 閲覧権限の可視範囲をインテリジェントに制御する機能を追加
    - ガバナンス設定権限を追加し、データガバナンス設定能力とデータ利用能力を分離
    - データ照会条件を拡充
  - データガバナンス設定にフロントエンドのスイッチを追加し、該当権限を持たないユーザーには入口を表示しません。

  ### 二、AutoGUI 自動プリコンパイル修正：AI が書いたアプリをそのまま利用可能に

  - AI が生成したフロントエンドコードは、ロジックが正しくても静的構文エラーで動かないことが多く、ユーザー自身がエラーを確認してエディタに戻り修正する必要がありました。AI によるアプリ作成の価値が最後の一歩で途切れてしまう問題です。
  - 本バージョンでは、AutoGUI のコード自律開発フローに自動プリコンパイル工程を追加しました。コード生成後に一度コンパイルし、静的構文エラーをシステムが自動で検査・修正してからユーザーへ引き渡します。ユーザーが受け取るのは、デバッグが必要なコードではなく、そのまま実行できるアプリです。

  ### 三、ログインアカウントの相互キック
