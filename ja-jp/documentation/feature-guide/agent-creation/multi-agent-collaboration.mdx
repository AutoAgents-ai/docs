### 機能概要

Multi-Agent コラボレーションはプラットフォームの中核的な高度機能であり、作成済みの Agent を再利用可能な「サブ Agent」としてカプセル化し、親ワークフロー内で呼び出すことをサポートします。この機能の中核的な価値は以下のとおりです。
能力の再利用とモジュール化：複雑な業務ロジックや特定のスキルを独立したサブ Agent としてカプセル化し、複数の親ワークフローで繰り返し呼び出すことで、重複開発を避け、開発効率を大幅に向上させます。
複雑タスクの分解と協調：異なる役割を持つ複数のサブ Agent を呼び出すことで、複雑なタスクの自動分解、並列処理、結果の統合を実現し、部門横断・長いフローの業務シナリオのニーズに対応します。
柔軟なヒューマン・イン・ザ・ループ協調：サブ Agent の実行終了後、ユーザーによる人的レビューとフィードバック（「満足したので次のステップへ」または「不満のため再実行」）をサポートし、AI の自律実行と人間による監督・判断の効率的な組み合わせを実現します。
この機能は自社開発の Multi-Agent アーキテクチャに基づいており、異なる Agent 間のシームレスな相互接続と協調呼び出しをサポートし、Agent により強力な実行判断能力を与えます。

### 画面説明

Multi-Agent コラボレーション機能は主に Agent の「プランニング」キャンバス画面で実現されます。この画面は Workflow 2.0 アーキテクチャを採用しており、「データフロー＋コントロールフロー」のデュアルライン設計を備え、ノードの設定は右側のドロワー形式で展開されます。複雑なシナリオにおける開発効率とキャンバスの可読性を大幅に向上させます。
画面の主な構成要素：
左側モジュール領域：「システムモジュール」「Agent」「ツール」の 3 種類に分かれています。「Agent」カテゴリには、作成・公開済みの Agent が一覧表示され、サブ Agent としてドラッグして利用できます。
中央キャンバス領域：モジュールをドラッグし、接続線を描画し、ワークフローを構築するためのビジュアル設計エリアです。サブ Agent は独立したノードとしてここにドラッグされます。
右側設定ドロワー：キャンバス内のサブ Agent ノードを選択すると、右側のドロワーにその設定画面が展開され、有効化条件や入出力変数などを設定できます。

### 操作フロー

前提条件：サブ Agent を作成・公開する
親ワークフローでサブ Agent を呼び出す前に、まず 1 つ以上のサブ Agent を作成・公開する必要があります。
サブ Agent の作成：「機能エントリー」に記載の手順に従って、新しい Agent ワークフローを作成します。設定ページで、その名前、説明、タイプ、Prompt などの基本情報を定義します。
サブ Agent ワークフローの設計：「プランニング」キャンバスに進み、サブ Agent のためにモジュールをドラッグして接続し、独立した機能ロジックを設計します。サブ Agent のワークフローが完全であり、必要な入力・処理・出力ノードを含んでいることを確認してください。
サブ Agent の公開：サブ Agent の設計が完了したら、「公開」操作を行う必要があります。公開後、その Agent は左側モジュール領域の「Agent」カテゴリに表示され、他のワークフローから呼び出せるようになります。公開とデプロイ機能の詳細は関連ドキュメントを参照してください。
親ワークフローでサブ Agent を呼び出す
親 Agent キャンバスに進む：「親 Agent」となるワークフローを作成または開きます。
サブ Agent ノードをドラッグする：左側モジュール領域の「Agent」カテゴリで、公開済みのサブ Agent を見つけて選択し、中央キャンバス領域の適切な位置にドラッグします。
サブ Agent ノードの設定：
有効化条件：キャンバス内のサブ Agent ノードを選択し、右側の設定ドロワーで「連動有効化」または「いずれか有効化」の条件を設定し、そのサブ Agent がどのような条件で実行を開始するかを決定します。
入出力（変数の受け渡し）：サブ Agent はメモリ変数の受け渡しに対応しています。設定ドロワーでは、親ワークフローからサブ Agent に渡す入力変数、およびサブ Agent が親ワークフローに返す出力変数を定義できます。これは通常「メモリ変数」モジュールを通じて実現され、ワークフロー内で一時変数を保存し、対話モジュールのコンテキスト長の制限を補い、長いラウンドの対話におけるコンテキストの継続と Agent 間のデータ受け渡しを実現します。
接続線によるフロー構築：サブ Agent ノードを上流モジュール（入力を提供）と下流モジュール（出力を受信）に接続線でつなぎます。各モジュールの左側が入力インターフェース、右側が出力インターフェースであり、接続線は必ず 1 つの出力インターフェースと 1 つの入力インターフェースをつなぐ必要があります。
ヒューマン・インタラクションの設定（オプション）：サブ Agent の実行終了後、親ワークフローではユーザーインタラクションノードを設計できます。例えば、サブ Agent の実行完了後、「ユーザーへの質問」や「確定回答」モジュールを通じてユーザーに結果を表示し、「満足」または「不満」の選択ボタンを提供できます。ユーザーの選択に応じて、親ワークフローは以降のステップを続行するか、サブ Agent を再実行するかを決定できます。
例：親ワークフローがサブ Agent を呼び出すロジック
典型的な親ワークフローには、以下のような流れが含まれます。
ユーザーからの質問：ユーザーの入力を受け取ります。
対話 / 情報処理：ユーザーの入力を初期処理し、重要な情報を抽出します。
サブ Agent A の呼び出し：処理後の情報を入力として、「データ分析」を担当するサブ Agent A を呼び出します。
サブ Agent A の実行：データ分析タスクを独立して完了し、結果を返します。
サブ Agent B の呼び出し：サブ Agent A の結果を入力として、「レポート生成」を担当するサブ Agent B を呼び出します。
ユーザーレビュー：サブ Agent B がレポートを生成した後、親ワークフローがユーザーにレポートを表示し、満足かどうかを確認します。
分岐処理：
ユーザーが「満足」を選択：親ワークフローは実行を続行し、例えばレポートをナレッジベースに保存したり、関係者に送付したりします。
ユーザーが「不満」を選択：親ワークフローはロールバックし、サブ Agent B を再実行するか、パラメータを調整して再実行します。
このモデルは Multi-Agent コラボレーションの柔軟性と拡張性を十分に体現しており、複雑な業務フローの構築をモジュール化・保守可能にします。

### 補足情報と意思決定の提案

権限と共有：サブ Agent の公開と呼び出しには権限管理が関わります。サブ Agent が公開済みであり、親 Agent の作成者または所属チームに呼び出し権限があることを確認してください。プラットフォームはワークフロー編成レベルでのユーザー単位の権限割り当て管理をサポートし、チームコラボレーションにおけるデータセキュリティと運用コンプライアンスを保証します。
デバッグと最適化：複雑な Multi-Agent ワークフローを構築する際は、プラットフォームの「単一ノードデバッグ」機能を十分に活用することを推奨します。この機能は、キャンバス内の単一ノード（サブ Agent ノードを含む）を個別にデバッグでき、ワークフロー全体を実行しなくてもノードのロジックと出力を検証できるため、開発・デバッグの効率を大幅に向上させます。
パフォーマンスとコスト：Multi-Agent コラボレーションはワークフローの複雑さと Token 消費量を増加させます。設計時にはタスクを合理的に分解し、不要なサブ Agent の呼び出しを避けるべきです。プラットフォームが提供するデータダッシュボードを参照して Total Token の消費量を正確に集計し、大規模モデルの利用コストの算出に役立てることができます。
適用シナリオの判断：Multi-Agent コラボレーションは、システム横断・役割横断・長いフローの複雑な業務、例えば契約審査、プロジェクト管理、深い調査レポートの生成などに特に適しています。単純な質問応答や情報検索タスクには、単一の Agent で通常十分であり、システムの簡潔性と実行効率を保つため、Multi-Agent アーキテクチャを導入する必要はありません。
