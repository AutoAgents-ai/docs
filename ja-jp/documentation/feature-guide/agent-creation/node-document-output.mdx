### 機能概要

ドキュメント出力モジュールは、プラットフォーム内で上流が生成したコンテンツを Word ドキュメントの形式で出力するための中核コンポーネントです。以下の 2 つの動作モードに対応しています。

### 直接出力モード：

テンプレートを使用しない場合、上流コンポーネントの出力内容を空白の Word ドキュメントに直接入力します。

### テンプレート差し込みモード：

プレースホルダーを含む Word ドキュメントのテンプレートをアップロードでき、システムが上流から渡された変数値を自動的にテンプレートの指定位置に差し込むことで、フォーマットが統一され、内容が個別化された構造化レポートを生成します。
このモジュールの中核的な価値は、ワークフロー内のデータを標準化されたドキュメントへ自動変換することにあり、レポート生成、契約書の草案作成、報告書の集約などのシナリオの効率を大幅に高めます。

### 準備作業

上流データソースの明確化：ドキュメントに出力したい内容がどの上流モジュールから来るのかを確定します。例えば、ユーザーが質問したテキスト、対話モジュールが生成した要約、情報抽出モジュールが抽出した構造化データなどです。
出力テンプレートの設計（オプション）：構造化されたレポートが必要な場合は、事前に Word でテンプレートを設計し、動的な内容を差し込みたい位置に {{プレースホルダーKey}} 形式のマークを付けます。例：{{顧客名}}、{{契約金額}}。

### モジュールのドラッグと基本設定

モジュールのドラッグ：ワークフローキャンバス左側のコンポーネントライブラリで「ドキュメント出力」モジュールを見つけ、キャンバス内の適切な位置にドラッグします。
モジュールの命名：モジュールの名前を変更します。例えば「見積書生成」など、フローの理解を容易にする名前にします。
有効化条件の設定：業務ロジックに応じて「連動有効化」または「いずれか有効化」を設定し、モジュールがどのような条件で実行を開始するかを決定します。

### モード1：直接出力（テンプレートなし）

適用シナリオ：1 段または複数段のテキスト内容を Word ドキュメントとして手早くまとめたい、フォーマットの要求がさほど高くない場合。
操作手順：
モジュールの設定ドロワーで、「カスタム情報入力の追加」エリアが使用されていない、またはテンプレートをアップロードしていないことを確認します。
上流モジュール（「対話」や「情報加工」など）の出力ノード（「回答内容」など）を、ドキュメント出力モジュールの「情報入力」ノードに接続します。
ワークフローがこのモジュールまで実行されると、上流のすべての出力内容が結合され、空白の Word ドキュメントとして生成・ダウンロードされます。

### モード2：テンプレート差し込み（テンプレートあり）

適用シナリオ：フォーマットが固定され、内容が動的に変化する標準文書（契約書、報告書、通知書など）を生成したい場合。
操作手順：
テンプレートのアップロード：モジュールの設定ドロワーで「テンプレートをアップロード」エリアを見つけ、事前に用意したプレースホルダー付きの Word ドキュメントをアップロードします。
カスタム情報入力の追加：テンプレートをアップロードすると、システムがカスタム情報入力の追加を促します。
「カスタム情報入力を追加」をクリックします。
表示された設定項目で、Key はテンプレート内のプレースホルダーの名称を厳密に記入する必要があります（例：顧客名）。名称は理解しやすい説明を記入できます（例：「顧客名フィールド」）。
上流モジュール内でこの Key に対応する出力ノードを、このカスタム情報入力ノードに接続します。
この手順を繰り返し、テンプレート内のすべてのプレースホルダーに対応するカスタム情報入力を追加します。
実行とダウンロード：ワークフローが実行されると、システムはすべての上流変数の値をテンプレートの対応する位置に差し込み、最終的な Word ドキュメントを生成してユーザーがダウンロードできるようにします。

### テストと公開

単一ノードデバッグ：キャンバス内でドキュメント出力モジュールを個別にデバッグし、ワークフロー全体を実行しなくても出力結果を検証でき、開発効率を大幅に向上させます。
完全なフローのテスト：ワークフロー全体を実行し、ユーザー入力やトリガー条件をシミュレートして、生成された Word ドキュメントが期待どおりであるかを確認します。
Agent の公開：テストに問題がなければ Agent を公開し、ドキュメント出力機能を実際の業務シナリオで使用できるようにします。

### よくある質問と注意事項

テンプレートフォーマットのサポート：アップロードした Word テンプレートは、基本的なフォント、フォントサイズ、段落フォーマットに対応しています。システムはテンプレート内のスタイルをできる限り再現しますが、過度に複雑なレイアウト（多層ネストしたテーブル、特殊なフォント効果など）は完全に保持できない場合があります。
プレースホルダーのフォーマット：テンプレート内のプレースホルダーは必ず {{プレースホルダーKey}} の形式を使用し、Key 名は設定した「カスタム情報入力」の Key と完全に一致させる必要があります。一致しない場合は差し込みできません。
上流変数のタイプ：上流から渡される変数値はテキスト型である必要があります。上流が JSON 構造の場合は、「情報処理」モジュールや「コードブロック」モジュールで先に解析・結合する必要がある場合があります。
ファイルのダウンロード：ドキュメント生成後、ユーザーの対話画面にダウンロードリンクが表示されます。大きなドキュメントの生成には数秒かかる場合があるので、ご注意ください。
モジュール実行終了：ドキュメント出力モジュールの実行が終了すると「True」が出力され、これを使って後続のフロー（指定されたメールアドレスへのドキュメント送信やナレッジベースへの保存など）をトリガーできます。
