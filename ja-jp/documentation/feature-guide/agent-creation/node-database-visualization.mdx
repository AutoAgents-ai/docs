### 機能概要

データ可視化モジュールは、プラットフォームの基本版における中核機能コンポーネントであり、構造化データ（特にデータベースのクエリ結果）を直感的なグラフに変換し、データインサイトと意思決定の効率を向上させることを目的としています。このモジュールは通常「データベースクエリ」モジュールと組み合わせて使用され、抽象的な JSON 形式のクエリ結果を、自動または必要に応じて棒グラフ、バーチャートなどの様々な可視化グラフに生成し、対話画面での二次編集・調整にも対応します。
中核的な価値：
利用の敷居の低減：専門的な可視化ツールやプログラミングスキルを習得しなくても、簡単な設定でデータのグラフ化表示を実現できます。
意思決定効率の向上：複雑なデータを直感的なグラフの形で示すことで、ユーザーが傾向を素早く把握し、差異を比較し、異常を発見するのを助けます。
フローのシームレスな連携：ワークフロー内の重要なノードとして、可視化結果を後続のモジュール（「確定回答」「ドキュメント出力」など）に直接渡すことができ、データクエリ・可視化・結果配信までの自動化されたクローズドループを実現します。
適用シナリオ：
業務レポートの生成：売上データや財務データを自動的に月次 / 四半期のトレンドグラフに変換します。
データ分析レポート：業界調査や競合分析レポートに、自動生成された比較グラフを挿入します。
Agent 対話出力：Agent がユーザーの質問に回答する際、結果をグラフの形で直接表示し、対話体験を向上させます。

### 機能エントリー

データ可視化モジュールは独立した機能ノードとして、プラットフォームのビジュアルワークフロー編成キャンバスに統合されています。この機能へのエントリー手順は以下のとおりです。
ログインとキャンバスへの移動：プラットフォームにログインし、対象の Agent の「プランニング」キャンバス編集画面に進みます。
モジュールの検索：キャンバス左側のコンポーネントライブラリで「データベース」カテゴリを見つけて展開します。
ノードのドラッグ：「データベース」カテゴリの下で「データ可視化」モジュールを見つけ、キャンバス内の適切な位置にドラッグします。
命名と有効化：キャンバスにドラッグしたモジュールの名前を変更し、業務ロジックに応じて「連動有効化」または「いずれか有効化」の条件を設定します。

### データ可視化画面

この画面はグラフ生成パラメータを設定するために使用され、コアパラメータには以下が含まれます。
連動有効化 / いずれか有効化：ブール型入力。モジュールの実行条件を設定するために使用します。「連動有効化」は上流のすべての条件が True の場合に実行することを表し、「いずれか有効化」は上流のいずれかの条件が True の場合に実行することを表します。
元データ：テキスト型入力。上流の「データベースクエリ」コンポーネントが出力するクエリ結果（JSON 形式）が入力データとなります。
グラフタイプ：ドロップダウン選択ボックス。ニーズに応じて生成するグラフの種類（棒グラフ、バーチャートなど）を選択します。このパラメータは省略可能で、未設定の場合はフロントエンドがデフォルトで自動入力します。
モジュール実行終了：ブール型出力。このモジュールの実行が終了すると、出力値は True となり、通常は下流フローのトリガーに使用されます。

### 操作フロー

以下では、「データベースクエリ＋データ可視化」を組み合わせた簡単なワークフローを実行する例を用いて、具体的な操作手順を説明します。
ステップ1：前提準備 - データベースクエリノードの追加
クエリノードのドラッグ：ワークフローキャンバス左側のコンポーネントライブラリの「データベース」カテゴリで、「データベースクエリ」モジュールをキャンバスにドラッグします。
クエリパラメータの設定：
データベースの選択：「データベース」ドロップダウンメニューで、設定済みのデータベース（jointpilot や自社データベースなど）を選択します。
SQL 文の記述：「SQL 文」入力欄にクエリ文を記述します。例：SELECT \* FROM sample_table WHERE condition = 'value' LIMIT 10;。
実行テスト：「実行」または「テスト」ボタンをクリックし、「出力」エリアで JSON 形式のクエリ結果を確認します。
ステップ2：データ可視化ノードの追加と設定
可視化ノードのドラッグ：左側のコンポーネントライブラリの「データベース」カテゴリで「データ可視化」モジュールを見つけ、キャンバスにドラッグして「データベースクエリ」ノードの後に配置します。
データ接続の確立：「データベースクエリ」ノードの「クエリ結果」出力ポートを、「データ可視化」ノードの「元データ」入力ポートに接続します。
グラフパラメータの設定：
有効化条件の設定：業務ロジックに応じて「連動有効化」または「いずれか有効化」を設定します。
グラフタイプの選択：「グラフタイプ」ドロップダウンボックスで必要なグラフスタイル（棒グラフなど）を選択します。
ステップ3：ワークフローの実行と結果の確認
保存とトライアル実行：現在のワークフローを保存し、キャンバス右上の「トライアル実行」ボタンをクリックします。
トリガー条件の入力：ポップアップした対話画面で、「データベースクエリ」ノードをトリガーできる質問または指示を入力します。
可視化結果の確認：システムが自動的にクエリを実行し、グラフを生成します。対話画面で生成された可視化グラフを直接確認でき、二次編集・調整にも対応しています。
ステップ4：結果の受け渡しと応用（オプション）
生成された可視化グラフは変数として、後続の「確定回答」モジュール（ユーザーへの固定的な回答用）や「ドキュメント出力」モジュール（レポート生成用）に直接渡すことができ、ワークフローの自動化されたクローズドループを実現します。
注意事項：
データフォーマット：上流の「データベースクエリ」モジュールが出力する JSON データの構造が明確で、フィールドが明示されていることを確認し、グラフの各軸に正しくマッピングできるようにしてください。
権限管理：現在のユーザーが選択したデータベースへのクエリ権限を持ち、生成された可視化結果へのアクセス権限を持っていることを確認してください。
グラフの編集：対話画面の二次編集機能により、ユーザーは実際のニーズに応じてグラフのスタイルを調整し、表示要件に合った結果にすることができます。
以上の手順により、プラットフォームでデータ可視化モジュールを効率的に活用し、無味乾燥なデータを明確なインサイトに変換して業務の意思決定を支援できます。
