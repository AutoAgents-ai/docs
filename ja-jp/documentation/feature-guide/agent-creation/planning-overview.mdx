---
title: "プランニング概要"
---

「プランニング」とはその名の通り、Agent の能力設計を指します。Agent の実行時には、システムは事前に設計されたフローに従って各モジュールを順次実行し、目的の効果を実現します。利用者がより理解しやすく設定できるようにするため、本プラットフォームの「プランニング」機能では、ドラッグ＆ドロップによる接続によって各機能モジュールを連結する方式を採用しています。これにより「タスクプランニング」がより分かりやすく使いやすくなり、かつ強力なカスタマイズ能力を備えています。
全体のプロセスはブロックを組み立てる作業に似ており、各モジュールはそれぞれ独自の能力を持っています。これらの「ブロック」を適切に組み合わせることで、専用の Agent を構築できます。各モジュールの機能に慣れることで、Agent の能力をより全面的に理解できるようになります。

### 画面の機能

モジュールエリア
「プランニング」ページに入ると、ページ左側のエリアがモジュールエリアです。現在、本プラットフォームのモジュールはシステムモジュール、Agent、ツール、MCP の 4 種類に分かれています。
システムモジュール：AI の能力と連携し、入力テキストに対して情報加工やナレッジベース検索などの処理を行います。
Agent：1 つの Agent のタスクプランニングの中で、公開済みの Agent を呼び出し、より複雑な能力のプランニングを行うことができます。
ツール：よく使うツールをパッケージ化し、Agent がサードパーティの能力と連携できるように拡張します。企業は自社のニーズに応じて、独自にツールを開発することも可能です。
MCP：汎用プロトコルにより、Agent アプリケーションと外部ツール・データソースとのインタラクションの壁を取り払い、開発効率と柔軟性を高めます。

キャンバスエリア
キャンバスエリアは「プランニング」の設計エリアです。モジュールエリアのコンポーネントをドラッグ＆ドロップでキャンバスに移動し、線で接続することで、各モジュールの能力を組み合わせることができます。
各モジュールにおいて、左側のインターフェースが入力、右側のインターフェースが出力です。接続時には「入力と出力」の 1 対のみを接続でき、「入力と入力」または「出力と出力」を接続することはできません。
接続を誤った場合は、線の中央にある「×」をクリックすることで接続を削除できます。

Agent 機能エリア
共有：現在の Agent を外部へ共有します。複数の共有方式に対応しています。
Http アプリケーション：リンク形式で Agent を共有し、この Agent をウェブページに埋め込むこともサポートしています。
API サービス：外部システムやアプリケーションから API インターフェース形式で呼び出すことをサポートします。
MCP Server：この Agent を MCP 形式にパッケージ化することをサポートします。
アプリケーション統合：外部アプリケーション「元知」への統合をサポートします。
削除：現在の Agent を削除します。
保存：Agent の現在のオーケストレーションと設定を保存します。
公開：この Agent を「Agent マーケットプレイス」に公開します。

モジュールの構造
各モジュールは 3 つの部分から構成されます。
左上：モジュール入力エリア。接続ノードから情報を入力します。
中央：モジュール設定エリア。ここでモジュールのパラメータや Prompt などの内容を設定します。
右下：モジュール出力エリア。モジュール実行後の情報を出力します。

黄色のノード：ブール型の数値で、他のブール型ノードと接続します。
青色のノード：文字列型で、テキスト情報、画像情報、ドキュメント情報の 3 種類に細分化され、同じ情報型のノードと接続します。
紫色のノード：ナレッジベース検索結果専用で、ナレッジベース検索結果の入出力に使用します。
赤色のノード：任意の型で、For Each モジュール内でのみ使用され、この値の型は JSON 配列または対象オブジェクトである必要があります。
接続の原則：同じ型のノード同士は接続可能ですが、異なる型のノードは接続できません。
