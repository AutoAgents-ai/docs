title: "情報抽出モジュール"
---

概要
簡単に言えば、このモジュールは「鋭い読解力を持つアシスタント」のような存在です。長文のファイルを渡すだけで、その中の「核心となる重要情報」を的確に抜き出し、システムが理解できる整った形式に整理してくれます。これにより、後続の処理をスムーズに進めることができます。

### モジュールの構造（入力と出力）

ワークフロー内の他のコンポーネントと同様に、この「アシスタント」にもタスクを受け取る「入力口」と、作業結果を引き渡す「出力口」があります。
入力口（入力ノード）：アシスタントはいつファイルの確認を始めるか？
起動スイッチ（実行ロジック）：
連動起動： 上流のすべてのステップが完了して初めて処理を開始します。
いずれか起動： 上流のステップのいずれか 1 つが完了すれば、すぐに処理を開始します。
受け取るデータ（コンテンツ入力ロジック）： 「ドキュメント情報」と呼ばれるデータ（つまり、アシスタントが読み取り・抽出すべき元のドキュメント内容）を受け取ります。
出力口（出力ノード）：アシスタントは作業完了後に何を引き渡すか？
出力するデータ（コンテンツ出力ロジック）： 抽出が完了すると、整理済みの抽出結果（システムが読み取れる JSON 形式のデータ）を次の工程へ引き渡します。
作業状況（実行ロジック）：
実行成功 または 実行異常： これは「二択」の報告です（正常に重要情報を抽出できたか、何らかの理由で処理が中断してエラーになったかのいずれかです）。
モジュール実行終了： これは最終的な総括です。このアシスタントが作業を終えれば（成功・エラーのいずれであっても）、このスイッチがオンになり、後続の工程に「このステップは完了したので、次に進んでよい」と通知します。

### モジュール内部の設定方法（抽出ルールの設定）

このコンポーネントを開いたら、この「読解アシスタント」に適した「拡大鏡」を用意し、どの種類のファイルに対してどの解析方法を使うべきかを指定する必要があります。
「抽出設定」では、2 段階の選択を行います。まずファイルタイプを選び、次に解析方法を選びます。システムは一般的なファイルタイプを複数（8 種類から 1 つ）用意しており、各タイプにはそれぞれ専用の「解析メソッド」が用意されています。
① 総合万能型 (all)： \ 解析方式：auto（自動）*。最も手間のかからない選択肢で、システムに判断を任せます。
② 表形式ファイル (excel)： \ 解析方式は 3 択：general（汎用）、tika、excel*（表専用解析）。
③ 音声ファイル (voice)：
解析方式：general（汎用）。音声に含まれる情報を抽出します。
④ PDF ファイル (pdf)： （PDF は構造が最も複雑なため、システムが提供するツールも最も多くなっています）
解析方式は 5 択：mineru、general（汎用）、tika、pp_structure_v3（レイアウト構造の識別が得意）、paddleocr-vl（図表・文字認識が得意）。
⑤ ドキュメントファイル (document、Word など)：
解析方式は 2 択：general（汎用）、tika。
⑥ プレーンテキストファイル (text)：
解析方式は 2 択：general（汎用）、tika。
⑦ スライドファイル (powerpoint、PPT など)：
解析方式は 2 択：general（汎用）、tika。
💡 応用テクニック：複数ルールの追加
このフローの中に PDF と Excel が両方存在する場合はどうすればよいでしょうか？ご安心ください。この設定項目の横に「追加」ボタンがあります。これをクリックすると、複数の抽出設定を同時に追加できます（例：PDF 専用のルールを 1 つ設定し、さらに Excel 専用のルールをもう 1 つ追加するなど）。これにより、「アシスタント」はさまざまな複雑なタスクに余裕を持って対応できます！
