### 機能概要

データベースクエリモジュールは、プラットフォームが開発者向けに提供する重要なデータ処理ツールであり、マイクロアプリ編成過程における構造化データへのアクセスニーズを解決することを目的としています。開発者はデータベースの接続プールや複雑なドライバを直接管理する必要なく、簡単な設定でデータ検索を実行し、クエリ結果を後続の業務ロジックや AI モデルにシームレスに統合できます。
このモジュールの中核的な価値は以下のとおりです。
利用の敷居の低減：低レベルの接続コードを記述する必要なく、ビジュアル設定だけでデータクエリを完了できます。
開発効率の向上：構造化データのクエリ能力を直接ワークフローに組み込み、業務フローとデータ処理の一体化を実現します。
データセキュリティの確保：操作権限を厳格に制限し、現在はクエリ（SELECT）操作のみをサポートしており、未承認のデータ書き込み、変更、削除を効果的に防止します。

### 機能エントリー

データベースクエリモジュールは独立した機能ノードとして、プラットフォームのビジュアルワークフロー編成キャンバスに統合されています。この機能へのエントリー手順は以下のとおりです。
モジュールのドラッグ：ワークフローキャンバス左側のコンポーネントライブラリの「データベース」カテゴリで「データベースクエリ」モジュールを見つけ、キャンバス内の適切な位置にドラッグします。
モジュールの命名：キャンバスにドラッグしたモジュールの名前を変更し、フローの理解や以後の管理を容易にします。
有効化条件の設定：業務ロジックに応じて「連動有効化」または「いずれか有効化」を設定し、モジュールがどのような条件で実行を開始するかを決定します。

### データベースクエリ画面

この画面は標準的な SQL クエリを設定するために使用され、コアパラメータには以下が含まれます。
データベース：ドロップダウン選択ボックス。デフォルトのオプションはプラットフォームが提供する jointpilot データベースです。自社のデータベースを使用する場合は、事前にプラットフォームの管理画面で設定を完了しておく必要があり、その後こちらで選択できるようになります。
SQL 文：テキスト入力欄。クエリ文を記述するために使用します。ご注意ください。現在はクエリ（SELECT）文の実行権限のみが開放されています。更新、挿入、削除など他の操作が必要な場合は、プラットフォームの担当者に連絡して相談してください。
出力：読み取り専用の表示エリア。クエリを実行すると、システムはここに返されたデータ結果を JSON 形式で表示します。

### 検索エンジンデータベースクエリ画面

この画面は検索エンジン専用のクエリを設定するために使用され、コアパラメータには以下が含まれます。
検索エンジンデータベース：ドロップダウン選択ボックス。プラットフォームには「衆標標訊」検索エンジンがあらかじめ組み込まれています。他の自社の検索エンジンデータベースに接続する必要がある場合は、まずプラットフォームの担当者に連絡して管理画面に設定してもらう必要があります。
DSL 文：テキスト入力欄。特定の検索エンジンの文法規則に準拠した Domain Specific Language のクエリ文を記述するために使用します。
出力：読み取り専用の表示エリア。クエリ実行後、結果は同様に JSON 形式で返されます。
重要な注意事項：
権限の制限：データベースクエリツールは現在、クエリ（SELECT）操作のみをサポートしており、データの書き込み、変更、削除はサポートしていません。これによりデータの安全性を確保しています。
複雑なクエリ：「衆標標訊」検索エンジンのフィールド構造とクエリ文法は比較的複雑であるため、初めて使用する際はプラットフォームの担当者に連絡してサポートを受けるか、サンプルを参考にすることを推奨します。
自社データベースの設定：自社のデータベースを使用する前に、管理者がプラットフォームの管理画面で接続情報（アドレス、ポート、ユーザー名、パスワードなど）の設定を完了させておく必要があります。

### 操作フロー

以下では、簡単なデータベースクエリを実行する例を用いて、具体的な操作手順を説明します。
ステップ1：クエリノードの追加
マイクロアプリ編成のキャンバス内で、ツールボックスから「データベースクエリ」ノードを適切な位置にドラッグします。
ステップ2：クエリパラメータの設定
キャンバス内のノードをクリックし、右側にポップアップする設定パネルで以下を設定します。
データベースの選択：「データベース」ドロップダウンメニューで、デフォルトの jointpilot を残すか、設定済みの自社データベースを選択します。
SQL 文の記述：「SQL 文」入力欄にクエリを記述します。例えば、SELECT \* FROM sample_table WHERE condition = 'value' LIMIT 10; と入力します。
ベストプラクティス：SELECT \* を使用せず、必要なフィールドを明確に指定することで、ネットワーク転送量を減らし、クエリ効率を高めることを推奨します。
変数の参照：SQL 文では上流ノードが出力する変数を参照できます。形式は WHERE id = { { upstream_var } } のようになります（波括弧内のスペースを削除してください）。これにより動的なクエリが実現できます。
ステップ3：実行と結果の取得
設定パネル下部の「実行」または「テスト」ボタンをクリックします。
システムが SQL 文を実行し、「出力」エリアに直接クエリ結果が表示されます。結果は JSON 配列であり、各オブジェクトが 1 行のデータを表し、フィールド名はデータベースの列名に対応します。
この JSON 出力は変数として、後続の大規模言語モデル（LLM）ノード、API ツールノード、またはテキスト処理ノードに直接参照・処理させることができます。

### 検索エンジンデータベースクエリのフロー

操作フローは上記と同様ですが、以下の点が異なります。
「検索エンジンデータベースクエリ」ノードを選択する必要があります。
「検索エンジンデータベース」で「衆標標訊」を選択します。
「DSL 文」に、その検索エンジンの要件に適合するクエリ文法を入力します。
実行後、同様に JSON 形式の検索結果が得られます。
ベストプラクティスと注意事項
クエリの最適化：大量のデータが返される可能性のあるクエリについては、必ず SQL 文で LIMIT 句を使用して返す行数を制限し、応答のタイムアウトやフロントエンドのレンダリング負荷を回避してください。
エラー処理：ワークフロー内でデータベースクエリノードの後に分岐判定ノードを接続し、クエリの成否や結果が空かどうかに応じて異なる後続フローを設計することを推奨します。
結果処理：返された JSON データは「JSON key 値抽出」や「JSON データ解析」ツールノードと組み合わせて、特定のフィールドを迅速に抽出し、さらなるデータ変換や表示を行うことができます。
権限管理：データベース接続へのアクセス権限は、プラットフォームの【データ権限管理】モジュールを通じてきめ細かく割り当てることができ、部門、担当者、ロール、または事前定義されたポリシーに基づいた権限付与に対応し、データの安全性を確保します。
