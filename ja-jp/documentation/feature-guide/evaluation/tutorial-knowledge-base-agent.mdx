ナレッジベース Agent は、現在人気のあるもう一つのツールの種類です。個人／企業独自のデータを大規模言語モデルと組み合わせることで、大規模言語モデルの知識範囲をさらに拡張し、業務との結びつきをより緊密にすることができます。
Agent の設定過程において、Agent 設定ページで「ナレッジベース」を関連付けて選択すると、設計ページに新たに「ナレッジベース検索」モジュールが追加されます。今回の事例では、この「ナレッジベース検索」モジュールの機能設計を中心に紹介します。

### キャンバス設計

Agent のキャンバス設計では、この時点で「ナレッジベース検索」モジュールが1つ追加され、「ナレッジベース」にアップロードされた資料を活用して、AI による大規模言語モデル関連の質問への回答を支援します。その具体的なロジックは以下の通りです。
接続線1：「ユーザー質問」モジュールを通じてユーザーの入力情報を取得し、「ユーザー質問」として出力します
「ナレッジベース検索」モジュールは「情報入力」を通じてユーザーの質問を受け取り、その後以下の手順を実行します：
「ユーザー質問」をベクトル化し、「大規模言語モデル」ナレッジベース内の既存のコンテンツ切片とベクトル検索を行います
検索結果を類似度順にソートし、類似度の高い切片を優先して返します
検索完了後、「ナレッジベース検索」モジュールの3つの出力接続線はそれぞれ2つのモジュールへ向かい、ロジックは以下の通りです：
接続線2：「ナレッジベース検索」の結果、条件を満たす切片コンテンツがない場合は、「固定応答」モジュールをトリガーし、ユーザーに「申し訳ありませんが、この質問には今のところお答えできません。まだ学習が必要です」と返答します
接続線3：「ナレッジベース検索」の結果、条件を満たす切片コンテンツが見つかった場合は、「インテリジェント対話」モジュールをトリガーし、プロンプト、「ナレッジベース検索結果」（接続線4）と「ユーザー質問」（接続線5）を合わせて「インテリジェント対話」モジュールに渡し処理します。
「インテリジェント対話」モジュールは上記3つの情報入力を受け取った後、以下の手順を実行します：
プロンプト、ユーザーの質問、およびナレッジベース検索結果を Tiangong 大規模言語モデルに渡します
大規模言語モデルが加工処理を行い、ユーザーへ回答します

「ナレッジベース検索」モジュールでは、「ナレッジベース類似度」と「ナレッジベース単回検索上限」という2つのパラメータを確認できます。これらはナレッジベースのベクトル検索結果（最終的にマッチする切片の数）と返却結果（返却される切片の数）を制御するものであり、使用時にはナレッジベースからより良い結果が得られるよう、これらの数値を調整する必要があります。

### ナレッジベース類似度

ユーザーの質問と検索結果との類似度を制御します。類似度の数値が高いほど、検索でマッチする結果は少なくなる可能性があります。したがって、ユーザーの質問については、ナレッジベースの内容とユーザーの質問内容に基づいてシーンを検討する必要があります。通常、類似度は 0.6〜0.9 程度に調整することを推奨します。

### 単回検索上限

ナレッジベースで検索を行う際に、検索結果として出力する件数の上限を x 件に設定します。ご注意いただきたいのは、取得する結果は多いほど良いわけではないという点です。モデルの最大 Tokens 数やナレッジベースのコンテンツ切片サイズなどの要因の影響を受けるため、具体的に利用可能な件数はパラメータを調整しながらテストを行い、より適切な上限値を選択してください。
