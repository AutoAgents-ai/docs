ナレッジベース以外にも、プラットフォームはより多様なシーンに対応するための複数のテキスト処理モジュールを提供しています。
例えば「情報分類」モジュールは、AI によって情報を分類し、分類結果に応じて異なるフローを実行できるようにします。「フィールド抽出」モジュールは、情報の中から指定したフィールドを抽出し、後続でそのフィールドを利用する場面で活用できます。「情報加工」モジュールは、情報を組み合わせ処理などの形で加工することができます。

### キャンバス設計

今回は「文豪」という Agent を例に、AI がさまざまな詩の作成リクエストをどのように処理し、異なる形式で出力を実現するかを説明します。そのため、この Agent 全体の設計としては、まずユーザーの意図を分類するための「情報分類」モジュールを配置し、分類結果に応じて文章作成を実行する構成になります。
接続線1：「ユーザー質問」モジュールを通じてユーザーの入力情報を取得し、「ユーザー質問」として出力します
「情報分類」モジュールは「情報入力」を通じてユーザーの質問を受け取り、その後以下の手順を実行します：
モジュールの prompt を「ユーザー質問」および会話コンテキストとともに Tiangong 大規模言語モデルに渡し、分類処理を行います
分類処理の結果を返し、次のモジュールの機能をトリガーします
接続線2〜4：続いて、分類結果に応じて異なる「インテリジェント対話」機能がトリガーされます。今回の Agent では、3 つの「インテリジェント対話」がそれぞれ「詩／童謡／歌詞」の作成を行い、ユーザーの要求に応じた出力を完成させます。
接続線5：「情報分類」モジュールでは、認識できなかった、または定義されていない分類を受け止めるために「その他」の分類を追加することを推奨します。これにより、ユーザーが自分の要求意図をより明確に表現できるよう誘導します。したがって、ユーザーのメッセージが上記のいずれの分類にも属さない場合は、「固定応答」モジュールをトリガーし、指定された内容を返します。
