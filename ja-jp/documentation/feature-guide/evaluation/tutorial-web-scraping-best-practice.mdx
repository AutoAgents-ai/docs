本記事では、新華網（Xinhuanet）の「新華文化」コーナーを例に、プラットフォームのクローラーツールの使い方と設定ロジックを紹介します😊
はじめに：プラットフォームクローラーの使用ロジック
ユーザーはプラットフォームの「ツール」モジュールで、プラットフォームの「Webスクレイピング」タスクを作成・利用できます。一般的に、ユーザーのニーズとしては、クローラーツールを利用して、多数のタイトル情報を含む Web ページを起点に、それらのタイトルに対応する詳細ページの具体的なコンテンツ情報を取得したいというケースが考えられます。これに基づき、プラットフォームのクローラーツールの利用ロジックは次の通りです：多数のタイトル情報を含む URL を入力 ➡️ 正規表現を利用して取得したいリンクを絞り込む ➡️ これらのリンクに対応する Web ページ上の必要なコンテンツを一括取得する。

### クローラータスクの新規作成

まず、プラットフォーム上でクローラータスクを新規作成する必要があります。作成方法：プラットフォームにログイン後、「ツール」－「公式ツール」－「Webスクレイピング」－ページ右上にある「取得タスクを新規作成」をクリックします。

### クローラー設定の説明

### 取得設定

タスクを開始するにあたり、まず情報源となる Web ページの URL を確定する必要があります。この URL には複数のニュースタイトルが含まれている必要があります（タイトルをクリックすると対応する具体的なニュースコンテンツのページへ移動します）。
今回のタスクでは、新華網の「新華文化」ページを使用します。URL は次の通りです：http://www.news.cn/culture/ この URL をコピーして「取得URL」欄に入力します。同時に、後で確認しやすいよう、新規作成したクローラータスクにわかりやすい名前（例：「新華網－新華文化」）をつけることができます。
続いて「次へ」をクリックし、「取得フィールド設定」ページに進みます。

### 取得フィールド設定（1）

まず、「取得フィールドを追加」ボタンをクリックします。これが最初の取得フィールドであり、そのロジックは次の通りです：先ほど入力した URL に基づき、その URL に含まれる取得対象のニュースリンクを絞り込み、リンクを1件ずつ開いてニュースコンテンツを取得します。また、この URL には多種多様なニュースリンクが多く含まれている可能性があるため、各リンクの特徴を観察し、正規表現を使って必要なリンクを絞り込む必要があります。

<Frame>
  <img src="/images/documentation/ch6_6.10.10.4_0265.png" alt="Webスクレイピングツールのベストプラクティス" />
</Frame>

「フィールドキー」：ニュースリンクを提供する URL として、ここではフィールドキーを「all」に設定できます（正規表現による絞り込み後のすべてのニュースリンクを抽出することを表します）。なお、フィールドキーの名称は後続の Agent の動作と関連付けられるため、プラットフォームに慣れていない方は、あらかじめ用意されたいくつかのキー名をそのまま使用することをお勧めします。むやみに名前を変更しないようにしてください🤔
「フィールドの説明」：これはキーの説明です。このサイトから絞り込まれるのは実際には各ニュースのリンクアドレスであるため、「ウェブページ」と名付けるとよいでしょう。この説明はユーザー自身の理解に応じて自由に記入でき、個性を出すことができます👏🏻
「フィールドタイプ」：プルダウンには「string」（ウェブページ内のテキストコンテンツを抽出）と「ウェブページ」（リンクを抽出）の2つの選択肢があります。今回のタスクでは、Web ページのリンクを抽出するため、「ウェブページ」を選択してください。
フィールド抽出ルール：これは Web ページのコードに基づいて設定する抽出ルールです。この抽出ルールに対応するのは、必要とするニュースのページです。ここでは正規表現でリンクを絞り込む必要があります。以下の2枚の図を参考にすると、必要なニュースのリンクにはいずれも「/culture/」が含まれていることがわかるため、これに基づいて正規表現を設定できます。

### 取得フィールド設定（2）

### タスクの開始

クローラータスクページに戻り、クローラーを起動する前に、タスクの「定期取得」の時間間隔を設定する必要があります。プラットフォームには「分」「時間」「日」の3段階の取得間隔があり、ニーズに応じて設定できます。この部分の入力が完了したら「起動」をクリックすると、クローラータスクが即座に実行を開始します。
しばらく待つと、「取得リンク数」を確認することで、クローラーが Web ページのコンテンツを正常に取得できたかどうかを確認できます。また、対応するナレッジベースで、取得したコンテンツが要求した形式でナレッジベースに格納されているかどうかを確認することもできます。

### 補足：クローラータスクに対応するAgentの設計

この部分では、クローラーと連携する Agent の背後にある設計ロジックを簡単に紹介します。
前述の通り、各ニュースページで取得が必要なキーは主に title、content、date の3つのフィールドで、それぞれ Web ページ上のニュースのタイトル、本文、公開日という3つの部分に対応しています。実際には、それぞれの内容について、プラットフォームはキー名で名付けられた変数に保存します。また、正規表現で抽出したリンクについても、プラットフォームは自動的にそのリンクの URL アドレスを保存し、これも1つの変数に格納します。Agent を設計する際には、プラットフォームのロジックに従い、これらの変数を自身が必要とする形式に応じて変換・組み立て、最終的にナレッジベースへ格納する必要があります。
今回のタスクでは、各ニュースページの内容をナレッジベースの1つの切片に保存する必要があります。具体的には、ニュース本文（content）をナレッジベース切片の内容に保存し、ニュースタイトル、URL アドレス、公開時刻を切片のタイトルに保存します。切片のタイトルについては、Agent 設計における「固定応答」モジュールを使って、ニュースタイトル、URL アドレス、公開時刻を必要な形式で表現し、ナレッジベースに格納することができます。
