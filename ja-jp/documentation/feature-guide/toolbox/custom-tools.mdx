リクエストメソッドの説明
カスタムツールは5種類のリクエストメソッドをサポートしています。詳細は以下の通りです。
GET（取得）
定義：GET リクエストはサーバーに対してリソースへのアクセスを要求するために使用され、情報の照会や取得に利用されます。リクエストパラメータは URL 経由で渡され、サーバーの状態を変更することはありません。
利用シーン：ユーザーリストの照会、記事詳細の取得など。
例：ある商品の価格を照会する：GET https://api.example.com/products/123。123 は商品 ID です。
POST（送信）
定義：POST リクエストはサーバーにデータを送信するために使用され、新しいリソースの作成やデータ処理に利用されます。データはリクエストボディを通じて送信されます。
利用シーン：新規ユーザー登録、フォーム送信、ファイルアップロードなど。
例：新規ユーザーアカウントを作成する：POST https://api.example.com/users、リクエストボディにはユーザー名やパスワードなどの情報を含みます。
PUT（置換）
定義：PUT リクエストはサーバー上の既存リソースを置換または新規リソースを作成するために使用され、完全なリソースデータの提供が必要です。
利用シーン：ユーザープロフィールの更新、ファイル内容の置換など。
例：ユーザープロフィールを更新する：PUT https://api.example.com/users/456、リクエストボディには更新後のユーザー情報をすべて含み、456 はユーザー ID です。
DELETE（削除）
定義：DELETE リクエストはサーバー上の指定リソースを削除するために使用され、操作は冪等であり、繰り返し実行しても結果は同じです。
利用シーン：ファイルの削除、ユーザーアカウントの削除など。
例：ブログ記事を削除する：DELETE https://api.example.com/blogs/789、789 は記事 ID です。
PATCH（部分更新）
定義：PATCH リクエストはリソースの一部を更新するために使用され、変更が必要な属性のみを指定すればよく、PUT よりも柔軟です。
利用シーン：ドキュメントの特定フィールドの変更、ユーザー情報の一部更新など。
例：記事タイトルのみを変更する：PATCH https://api.example.com/articles/1010、リクエストボディには新しいタイトルのみを含み、1010 は記事 ID です。
リクエストメソッドを選択する際は、実際の状況に応じてインターフェース仕様書の要件を参照してください。

### 認証方式の説明

ネットワークリクエストにおいて、認証はリクエスト元がリソースへのアクセス権を持つことを確認するために使用されます。よく使われる認証方式には Basic Auth、Bearer Token、Custom があります。詳細は以下の通りです。
Basic Auth 認証
定義：ユーザー名とパスワードを用いる基本的な認証方式です。
操作：ユーザー名とパスワードをコロンで連結し Base64 エンコードした上で、リクエストヘッダーに Authorization: Basic \<encoded-credentials\> を追加します。

### デバッグと検証

保存後、ステップ3のデバッグに進み、対応する入力を入力してインターフェースをリクエストします。デバッグの成否に応じて公開できるかどうかが決まります。テストに合格すれば公開可能です。テストに合格しない場合は保存はできますが公開はできません。

### ツールの公開

保存とデバッグが完了すると、新規作成したツールが一覧に対応するレコードとして表示されます

<Frame>
  <img src="/images/documentation/ch6_6.7.2.6_0227.png" alt="カスタムツール" />

一覧では編集、削除、公開、公開停止をサポートしています
注意：
デバッグに合格した Agent のみ公開できます
公開後のツールはオーケストレーション画面でドラッグして使用できます

### ツールを公開停止すると、ツールサイドバーには表示されなくなりますが、過去にこのツールを使用していた Agent には影響しません
