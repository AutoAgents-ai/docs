<Update label="September 4 - September 18" tags={["v2.1.0.0"]} rss={{ title: "Agentify v2.1.0.0", description: "Upgraded Agent parallel execution and test-case sets, Text2Agent auto-debug, model health visualization, and Skill file attachments, plus dashboard stats, knowledge-base citation badges, and bulk model replacement, with 19 bug fixes" }}>
  ## I. Release Overview

  This release focuses on upgrading Agent parallel execution and test-case sets, Text2Agent automatic debugging, model health visualization and governance, and Skill file/attachment expansion. It also brings data dashboard statistics, knowledge-base citation badges, and bulk model replacement in orchestration, with 19 bug fixes and multiple system optimizations.

  ## II. Core Changes

  ### 2.1 Agent Parallel Execution Engine

  Agent orchestration adds **parallel execution**, significantly improving efficiency while remaining compatible with serial mode:

  - Agents support both **serial / parallel** run modes; **existing data remains serial by default**, and the new parallel capability is enabled via a switch
  - Supports configuring **parallelism** (up to 16 per Agent; system-wide max 1000, configurable)
  - Parallel scheduling uses a **serial + parallel dual-queue** strategy:
    - **Serial**: `Speak` nodes, interruptible nodes, and write-memory nodes
    - **Parallel**: general processing nodes
  - Supports parallel execution in nested scenarios such as **sub-agents and for loops**

  ### 2.2 Test Cases and Automatic Debugging

  - Agent **component debugging** and **trial runs** both support adding **test-case sets**
  - Supports **Text2Agent automated debugging**, improving Agent orchestration and validation efficiency

  ### 2.3 Model Status Visualization

  Model management adds **status detection and alerting**:

  - Periodically detects model availability and response rate
  - Across **all model-selection entrances**—Agent orchestration, code-block IDE, Skills, Apps, and more—shows model health with **red / yellow / green** status indicators
  - Consumers can tell whether a model is available without extra troubleshooting

  ### 2.4 Skill Files and Attachments

  - Skills support **binary file storage** (common formats such as images, Word, PPTX, and PDF)
  - **Text2Skill** supports uploading files, images, and other attachments as reference materials
  - Further expands the material types and use cases Skills can carry

  ### 2.5 Knowledge Base Citation Badges

  After adding a knowledge base to an Agent component:

  - Supports displaying **citation badges** for retrieved content
  - When knowledge-base tool components are invoked during reasoning, also supports **badge generation and citation-source viewing**

  ### 2.6 Data Dashboard Statistics

  Added two model-invocation statistics summary tables:

  - **Agent** model-invocation statistics summary
  - **App** model-invocation statistics summary

  App model billing and chat records add an **`app_id`** field to improve dashboard query logic and performance.

  ### 2.7 Orchestration and Template Capabilities

  - Orchestration page supports **bulk model replacement**
  - Default backend **max_token** for intelligent nodes is adjusted to **32000** (Intelligent Dialogue / Agent nodes, Document Q&A nodes, Image Q&A nodes; previous default of 3000 was too small)
  - Agent component removes the "Max iterations" parameter field; backend default is **200** (configurable)
  - **Excel component** template-generation syntax optimizations:
    - When variable input is an array, it is automatically wrapped as `{"list": []}`
    - `for` / `hfor` loops support **Chinese variable names**
  - Template functions support passing arguments by **referenced variables**, for example: `[@["functionName", "*{{args1}}", "*{{args2}}", ...]@]`
  - Added **`KbMerge`** function: merge multiple knowledge-base query results and take TopK

  ## III. Other Updates

  - **System management**: User management supports configuring **whether to hide built-in system accounts**, meeting some customers' controls for non-natural-person accounts; the organization-tree area on the org structure page supports **drag-to-resize**
  - **Files and storage**: File-storage **instant upload** can detect whether historical files have already been deleted; file uploads **write directly to disk** instead of loading all content into memory; added **OFD** extension support and completed **Chinese font** adaptation
  - **Ops monitoring**: Provides service **liveness probes** and simple **monitoring APIs** to view backend system resource information, easing probe and monitoring integration
  - **Performance**: Optimized the Token-consumption statistics scheduled task to reduce MongoDB pressure; optimized knowledge-base chunk MongoDB indexes

  ## IV. Experience Changes

  The following adjustments change existing UI behavior, defaults, or operation paths:

  - **Agent parallel mode**: New orchestrations can enable parallel mode; **existing Agents remain serial by default** and require manually turning on the parallel switch
  - **max_token default**: Intelligent Dialogue / Agent / Document Q&A / Image Q&A nodes change from 3000 to **32000**
  - **Max iterations**: Agent component no longer shows this field in the UI; backend defaults to 200 (configurable)
  - **Model selection**: Red / yellow / green status indicators are added at model-selection entrances
  - **Orchestration page**: Adds a bulk model-replacement entry
  - **Keyword recognition component**: Removes Debug / Test-case tabs; after enabling document review, the debug-page upload entry and interactions are adjusted accordingly

  ## V. Bug Fixes

  ### 5.1 Agents

  - Fixed process interruption when encountering a **user question** during parallel execution
  - Fixed scrambled output during **sub-agent parallel** execution
  - Fixed an issue in parallel + sub-agent scenarios where **re-running the parent Agent** did not start from the parent Agent
  - Fixed sub-agents that should run in parallel but actually ran **serially**
  - Fixed components becoming unclickable after the orchestration page was **fully collapsed by left-right dragging**
  - Fixed errors in Agent **information classification** component debugging
  - Fixed errors in Agent **information extraction** component debugging
  - Fixed errors in the **PPT generation** component
  - Fixed errors when uploading TXT or OFD files in **Document Q&A**
  - Fixed Agent **expanded questions** still running empty and erroring when the model was empty
  - Fixed intermittent Python code-block failures loading third-party libraries (`patchelf` load failure) that caused subsequent code calls to fail

  ### 5.2 Knowledge Base and Skills

  - Fixed unresponsive **PPTX file parsing** in knowledge bases
  - Fixed **Text2Skill** translation not being displayed
  - Fixed **Text2Skill @ file** functionality not taking effect

  ### 5.3 Apps and UI

  - Improved an issue where some areas in the App module **could not copy text** (browser compatibility)
  - Adjusted App error prompt wording to **Chinese**
  - Fixed broken icons for **video-type files**
  - Fixed missing document-upload entry on the debug page after enabling the **document review** switch

  ### 5.4 Data Dashboard

  - Fixed incorrect **model names** shown for model-analysis related metrics
</Update>

<Update label="August 7 - August 21" tags={["v2.0.9.0"]} rss={{ title: "Agentify v2.0.9.0", description: "Refactored the resource permission system, added AutoGUI auto precompile-and-fix, and improved large-data loading and concurrency handling, with 23 bug fixes" }}>
  ## Release Overview

  This release refactors the resource permission system, adds AutoGUI auto precompile-and-fix so AI-generated apps are ready to run, and optimizes loading and concurrency for large-data scenarios. It includes 23 bug fixes.

  ## Core Changes

  ### I. Resource Permission System Upgrade

  - Permission granularity moves from "whether a resource type is accessible" down to resource and action dimensions.
  - **Covered resource types**: MCP, Apps, Skills, Custom Tools, Databases, and Models.
  - **Unified action model**: Read / Write / Review / Manage, with consistent semantics across all resource types.
  - **Data Management permission capabilities completed in sync**:
    - Control delete and edit actions by permission
    - Added intelligent visibility scope for view permissions
    - Added governance-settings permission, separating data-governance configuration from data-usage capabilities
    - Improved data query conditions
  - Data governance settings now include a frontend switch; users without the corresponding permission no longer see the entry point.

  ### II. AutoGUI Auto Precompile-and-Fix: AI-Generated Apps Ready to Run

  - Even when AI-generated frontend logic is correct, static syntax errors often prevent the app from running. Users previously had to inspect errors and return to the editor to fix them, interrupting the value of AI-built apps at the final step.
  - This release adds an automatic precompile step to AutoGUI's autonomous code-development flow: after code is generated, the system compiles it once, automatically checks and fixes static syntax errors, and then delivers the result. Users receive an app that can run directly, not a codebase that still needs debugging.

  ### III. Login Session Kick-out

  - Added login session kick-out capability, with a notification when a session is forced offline. Four modes are supported:
    - **global**: Global kick-out — logging in on any client kicks all other clients
    - **isolated**: Client-isolated kick-out (default) — terminal kicks terminal, Web kicks Web; terminal and Web do not affect each other
    - **terminal**: Kick-out among terminals only
    - **web**: Kick-out among Web clients only

  ### IV. Multi-tenant Configuration Switching

  - System configuration now supports tenant switching. The autoagents platform administrator can switch to any tenant to complete configuration; tenant-owned accounts do not have switching capability.

  ## Other Updates

  - **System configuration usage notes**: Added explanatory copy for each configuration item.
  - **Workflow version records on Agent publish**: Each publish retains the corresponding workflow version for version tracing.
  - **Organization-tree loading interaction redesign**: Redesigned frontend loading and interaction patterns to handle large-data scenarios.
  - **Thread-pool optimization**: Optimized the thread pool and its queue strategy.
  - **Smart terminal telemetry (capability preview)**: Provides reporting interfaces and observability for logs, conversations, and call chains. End-to-end integration with the terminal is not fully complete; this release is not yet recommended for formal troubleshooting or analysis.

  ## Experience Changes

  The following adjustments change existing UI behavior or operation paths:

  - **Skill details page**: The previous "Publish" action is now "Enable in Workflow".
  - **MCP in self-service mode**: The publish button is no longer shown, and the publish-request dialog no longer appears.
  - **Agent cards**: The action entry (three-dot menu) is hidden when no actions are available.
  - **History records**: Added a character limit of 50.

  ## Bug Fixes

  ### I. Permissions

  - Fixed an issue where users with Manage permission could not use the three share-page features and were shown a no-permission message.
  - Fixed an issue where users with Manage permission were missing the "Assign usage permission" button.
  - Fixed an issue where users with Manage permission were shown a no-permission message when opening usage records.
  - Fixed an error when entering the database details page with Read permission on a database.
  - Fixed an issue where the tenant administrator "System Configuration - Security Control" page failed to load.

  ### II. Modes and Configuration

  - Fixed an issue where switching between self-service and centralized modes failed.
  - Fixed an issue where MCP publish in self-service mode still showed the publish-request dialog.
  - Fixed an error when switching language after the tenant-admin account (autoagents) selected a tenant in system configuration.

  ### III. Workflows and Nodes

  - Fixed an issue where nodes of any type could not connect to downstream nodes.
  - Fixed an issue where switching a code block from Python to JS in the IDE left neither Python nor JS selected after returning to the component.

  ### IV. Models and Conversations

  - Fixed model extrabody override not taking effect, and added model error echo.
  - Fixed an issue where the settings dialog did not appear after searching in the model list and clicking the settings button.
  - Fixed an issue where switching chat tabs during streaming output caused content to disappear after returning to the original conversation.
  - Fixed Text2Agent generating two initial inputs on the second question.
  - Fixed history-record restore not taking effect.

  ### V. Pages and Data

  - Fixed a 500 error on the Data Management page.
  - Fixed abnormal data on the usage records page.
  - Fixed Agent usage records failing to display due to an internationalization issue.
  - Fixed abnormal positioning of the dictionary-management delete dialog.
