Knowledge base Agents are another popular type of tool. They combine an individual's or organization's proprietary data with a large language model, further expanding the model's knowledge and integrating it more tightly with your business.
When configuring an Agent, if you link a "Knowledge Base" on the Agent settings page, a new "Knowledge Base Search" module will appear on the planning page. This example focuses on the functional design of the "Knowledge Base Search" module.

### Canvas Planning

In the Agent's canvas plan, a "Knowledge Base Search" module is added, which uses the materials uploaded to the "Knowledge Base" to help the AI answer questions related to large language models. Its logic works as follows:
Connection 1: The "User Question" module captures the user's input and outputs it via "User Question."
The "Knowledge Base Search" module takes the user's question as input through "Information Input," and then performs the following steps:
It vectorizes the "User Question" and performs a vector search against the existing content chunks in the "Large Language Model" knowledge base.
It ranks the search results by similarity and returns the highest-ranked chunks.
Once the search is complete, the three output connections of the "Knowledge Base Search" module lead to two different modules, with the following logic:
Connection 2: If the "Knowledge Base Search" result contains no matching chunks, the "Fixed Reply" module is triggered, replying to the user with "Sorry, I can't answer this question yet—I still need to learn more."
Connection 3: If the "Knowledge Base Search" result contains matching chunks, the "Intelligent Dialogue" module is triggered, and the prompt, the "Knowledge Base Search Result" (Connection 4), and the "User Question" (Connection 5) are all passed to the "Intelligent Dialogue" module for processing.
Once the "Intelligent Dialogue" module has received the three inputs above, it performs the following steps:
It passes the prompt, the user's question, and the knowledge base search result to the Tiangong model.
The model processes this information and replies to the user.

In the "Knowledge Base Search" module, you'll see two parameters, "Knowledge Base Similarity" and "Knowledge Base Search Limit," which control the knowledge base's vector search results (the number of matched chunks) and the returned results (the number of chunks returned), respectively. In practice, these values need to be tuned to ensure the knowledge base returns better results.

### Knowledge Base Similarity

Controls the similarity between the user's question and the search results. The higher the similarity value, the fewer matching results may be returned. So when handling user questions, weigh both the knowledge base content and the nature of the user's question. We generally recommend setting the similarity value between 0.6 and 0.9.

### Search Limit per Query

When searching the knowledge base, this sets the maximum number of results (x) to return as output. Note that more results aren't always better—factors such as the model's maximum Token limit and the size of the knowledge base content chunks come into play. Adjust and test this parameter to find the limit that works best for you.
