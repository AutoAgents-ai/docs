A knowledge base is a collection of datasets. You can upload files in various formats (such as documents, spreadsheets, and slides) and parse them into datasets. Agents can generate responses based on one or more knowledge bases.

### Advanced Settings

Select a parsing method (such as Legal, Paper, Book, Manual, FAQ, etc.)
Specify the embedding model: An embedding model is an algorithm that converts text into vectors (numerical form) to capture the semantic information within the text. Specifying an embedding model determines how text is embedded into a high-dimensional space, so that semantically similar content ends up closer together in that space.
Set the chunk token count: The chunk token count refers to the number of tokens (words or subwords) contained in each "chunk" (or segment) when the system splits a document during processing. A token is the smallest unit the model uses when processing text — it can be a whole word or part of a word. The purpose of setting the chunk token count is to manage document size and processing efficiency. A larger chunk token count can accommodate more content but may increase computational complexity, while a smaller chunk token count enables more fine-grained text analysis but may require more chunks to process the entire document. Setting an appropriate chunk token count balances processing precision and efficiency.
Click "Confirm" to complete the creation
Note: Once an embedding model is selected, it cannot be changed, to ensure that all files in the knowledge base use the same embedding space.

To accommodate diverse document types, we provide multiple built-in parsing methods covering, but not limited to, legal documents, papers, books, manuals, and FAQs. Please note that once you select and use an embedding model to embed files, you will not be able to change that embedding model. All files within a given knowledge base must be embedded using the same embedding model, so that similarity can be compared and relevant content retrieved within the same embedding space.

### Knowledge Graph

### Feature Overview

The knowledge graph feature lets you enable graph extraction when creating a knowledge base. Uploaded documents are automatically parsed to generate entities and relationships, graph-based recall can be enabled during retrieval to improve results, and a visualization interface lets you intuitively view and manage entity relationships, helping users precisely understand and retrieve knowledge.

### Entry Point

In the left navigation bar, click the "Knowledge Base" module. On the "Created by Me" knowledge base list page, click the "+" card in the first position of the list to trigger the creation flow.

Creation dialog: The "Create Knowledge Base" dialog contains the full set of knowledge base configuration options, with graph extraction as the core toggle:

### Operating Instructions

Step 1: Enter the creation page. Click "Knowledge Base" in the left navigation bar, then click the "+" card on the knowledge base list page to open the creation dialog.
Step 2: Configure basic information. Fill in or select the basic knowledge base configuration (such as required fields like chunk token count and image parsing strategy).
Step 3: Enable graph extraction. Find the "Graph Extraction" toggle at the bottom of the dialog and click it to switch it to the blue "on" state, enabling knowledge graph generation.
Step 4: Complete the creation. After confirming that all configurations are correct, click the "Confirm" button to complete creation of the knowledge base with graph capability enabled, and you'll be automatically taken to the knowledge base detail page.

Step 1: Enter the Datasets page. After creating the knowledge base, you're automatically taken to its "Datasets" page.
Step 2: Upload documents. Click the upload area to select local documents (or drag and drop files directly) to complete the upload; the files will appear in the uploaded file list.
Step 3: Confirm auto-parsing. Keep the "Auto-parse" checkbox checked (enabled by default) to ensure the system automatically extracts knowledge and generates the graph.
Step 4: Update the knowledge base. After confirming the files are correct, click the "Update Knowledge Base" button. The system will automatically parse the documents, extract entities and relationships, generate the knowledge graph, and complete the knowledge base data update.

### Enable Graph Recall on the Retrieval Testing Page

  <img src="/images/documentation/ch6_6.5.1.16_0154.png" alt="Create Your First Knowledge Base" />
</Frame>

### Interface Description

Left navigation: The "Retrieval Testing" tab is currently selected, used to test the recall and re-ranking performance of the knowledge base.
Core configuration area:
Basic retrieval settings such as similarity threshold, vector similarity weight / keyword similarity, recall count, re-ranking model, and directory-based recall.
Graph recall toggle: A blue "on" state enables retrieval that combines knowledge graph associations for recall, improving retrieval results; when off, only traditional vector retrieval is used.
Graph recall weight and N-hop expansion: Used to configure the weight and relationship depth of graph recall, optimizing recall precision.
Test text input box: Used to enter test questions to verify retrieval performance.
Results area on the right: Currently shows "No data yet"; results will be displayed after testing.

### Operating Instructions

Step 1: Go to the Retrieval Testing page. Click "Retrieval Testing" in the left navigation to enter the retrieval configuration and testing page.
Step 2: Enable graph recall. Find the "Graph Recall" toggle and click it to switch it to the blue "on" state, enabling graph-based associative recall.
Step 3: Configure graph parameters (optional). Adjust parameters such as "Graph Recall Weight" and "N-hop Expansion" to optimize the scope and effectiveness of graph recall.
Step 4: Test retrieval (optional). Enter a question in the "Test Text" input box and click "Test" to verify retrieval performance combined with the graph.

### View the Knowledge Graph

<Frame>
  <img src="/images/documentation/ch6_6.5.1.19_0155.png" alt="Create Your First Knowledge Base" />
</Frame>

### Interface Description

Left navigation: The "Knowledge Graph" tab is currently selected, used to visually view the entities and relationships in the knowledge base.
Page header:
Title "Knowledge Graph," with the description: "The knowledge graph helps you visualize the entities and relationships in your knowledge base."
Statistics: The upper-right corner shows "Entities: 20 | Relationships: 18," providing an at-a-glance view of the graph's scale.
Expansion state: Shows "Expanded neighbors of 'XXX' | Showing 14 / 20 nodes," supporting node expand/collapse.
Search box: "Search nodes...," supporting quick lookup of graph nodes by entity name.
Graph visualization area:
Displays the knowledge graph as nodes and edges, with different colors distinguishing different communities (e.g., Community #0, #11, etc.). Nodes represent entities, and edges represent relationships between entities.
"Refresh Graph" button: Clicking it reloads the graph, syncing the latest entity and relationship data.
Bottom community bar: Shows the graph's community categories (e.g., 13 communities in total), supporting filtering of graph nodes by community.

### Operating Instructions

Step 1: Go to the Knowledge Graph page. Click "Knowledge Graph" in the left navigation to enter the graph visualization page; the system automatically loads the generated knowledge graph.
Step 2: View and interact with the graph.
You can drag the graph to adjust the layout, click a node to expand/collapse its neighboring nodes, and view entity relationships.
Enter an entity name in the search box in the upper-right corner to quickly locate the target node.
Step 3: Refresh the graph (optional). If the knowledge base data has been updated, click the "Refresh Graph" button in the lower-right corner to sync the latest entities and relationships and regenerate the visualization.
Step 4: Filter by community (optional). Click a category in the bottom community bar to filter nodes for the corresponding community, focusing on entity relationships within a specific domain.
