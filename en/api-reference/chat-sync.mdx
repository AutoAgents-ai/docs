---
title: "Agent Chat Non-Streaming API (Sync)"
---

The request parameters are largely the same as the [Agent Chat Streaming API](/en/api-reference/chat-stream); the difference is that this API returns the complete response result in a single response (not an SSE stream).

## Request URL

```
{{host}}/openapi/agents/chat/completions/v1
```

or

```
{{host}}/openapi/v2/chat/completions
```

## Request Method

`POST`

## Request Headers

Same as the [Agent Chat Streaming API](/en/api-reference/chat-stream#request-headers): supports ✅ Agent Token, ✅ personal credentials, optional `X-username`.

## Request Body Parameters

The parameters are identical to the [request body parameters of the streaming API](/en/api-reference/chat-stream#request-body-parameters) (`agentId`, `chatId`, `userChatInput`, `state`, `buttonKey`, `images`, `files`, `formData`, `debug`).

## Request Body Example

```json
{
    "agentId":"a2207c2f6d3d44d2b4a5dae5b5593750",
    "chatId": null,
    "userChatInput":"Mybatis",
    "images":[{"url":"your image url here"}],
    "files":[],
    "state":{
        "yourKey1":"yourValue1",
        "yourKey2":"yourValue2"
    },
    "buttonKey":"button id or name",
    "debug":false
}
```

## Response Body

| Field | Description |
| --- | --- |
| `chatId` | Conversation ID |
| `conversationId` | Current session ID; one conversation may contain multiple sessions |
| `state` | The environment variable parameters passed in, returned unchanged |
| `memory` | Variable information (key/value) generated during Agent execution, e.g. `{"memoryKey1":"memoryValue1"}` |
| `choices` | An array of reply content; there may be multiple reply entries. Each entry has the same structure as a single message in the [streaming response body](/en/api-reference/chat-stream#streaming-response-body) (fields such as `messageId`, `type`, `componentName`, `content`, `complete`, `finish`, `status`, `role`, `bill`, `referenceType`, `reference` have the same meaning) |

<Info>
Except for the final message with `finish:true`, each entry in `choices` represents a separate reply (a single session may contain multiple replies).
</Info>
