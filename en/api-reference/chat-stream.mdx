title: "Agent Chat Streaming API"
---

## Request URL

```
{{host}}/openapi/agents/chat/stream/v1
```

or

```
{{host}}/openapi/v2/chat/stream
```

## Request Method

`POST`

## Request Headers

Refer to the authentication section of the [API Specification](/en/api-reference/overview); supports ✅ Agent Token, ✅ personal credentials.

| Header | Description |
| --- | --- |
| `X-username` | `{Your UserName}`, the user's login name, optional. When passed, the system will call the API on behalf of this login name, and access logs, etc. will be recorded under this username. If not passed, the Token owner is used by default as the recorded caller identity. (v1.9.3+) |

## Request Body Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `agentId` | string | Yes | Agent UUID |
| `chatId` | string | No | Conversation ID, optional; leave empty for the first session. To retain context in subsequent sessions, include the `chatId` from the previous session's streaming response body in the next request |
| `userChatInput` | string | Yes | User input |
| `state` | object | No | Environment variable parameters passed in; keys/values are defined by the caller. Agent orchestration can access the corresponding parameter via `{{_state.yourKey}}`, e.g. `{"yourKey1":"yourValue1","yourKey2":"yourValue2"}` |
| `buttonKey` | string | No | Button name or button ID |
| `images` | array | No | Image question parameters; supports passing an image URL or a Data URI (supported by the AI chat component and image question component; not supported by other components), e.g. `[{"url":"http://imageUrl"}]` |
| `files` | array | No | Document Q&A / document review; see example below |
| `formData` | object | No | Form input; `formConfig` represents the form's display configuration, and `values` represents the user's key-value input, where each key corresponds to a key in `fields` within the display configuration |
| `debug` | boolean | No | Whether to enable debug mode, default `false`. When enabled, detailed request parameters, response parameters, and exception information are logged for every request, which can generate a large amount of data; if disabled, only information for failed calls is logged. It is recommended to set this to `false` or leave it unset in production environments |

## cURL Example

Replace `{{host}}` with your actual environment address, and `{authKey}`/`{authSecret}` with your credentials (see [API Specification](/en/api-reference/overview)):

```bash
curl -N -X POST "{{host}}/openapi/agents/chat/stream/v1" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer {authKey}.{authSecret}" \
  -d '{
    "agentId":"a2207c2f6d3d44d2b4a5dae5b5593750",
    "chatId": null,
    "userChatInput":"What is the internet",
    "images":[{"url":"your image url here"}],
    "files":[],
    "state":{
        "yourKey1":"yourValue1",
        "yourKey2":"yourValue2"
    },
    "buttonKey":"button id or name",
    "debug":false,
    "model": "model-id"
}'
```

## Streaming Response Body

The response is an SSE stream; each line starts with `data:` and carries a JSON object.

| Field | Description |
| --- | --- |
| `chatId` | Conversation ID |
| `conversationId` | Current session ID; one conversation may contain multiple sessions |
| `messageId` | Message ID identifying a reply message, which can be used for like/dislike feedback; has a value when `complete=true&finish=false` |
| `type` | Message type, see table below |
| `componentName` | Name of the current component |
| `content` | Streamed content; the format varies with `type` |
| `reasoningContent` | Reasoning/thinking content; only returned by reasoning models (e.g. deepseek-R1) |
| `thinkingElapsedMillSecs` | Time spent reasoning, in milliseconds; only returned by reasoning models |
| `complete` | `true` indicates that a particular reply within a streaming session has ended (a single session may contain multiple replies) |
| `finish` | `true` indicates that the entire streaming session request has ended |
| `status` | Message status: `1` normal message, `0` failed message, `-1` exception message |
| `role` | The role of the current message, generally user info or Agent info (avatar, name, etc.) |
| `bill` | Token consumption for a reply within the streaming session that has ended (`complete=true`) |
| `referenceType` | Reference type: `web_search` web search, `kb_search` knowledge base search, `kb_search_img_list` knowledge base image search |
| `reference` | Reference content; the format varies with `referenceType` |
| `references` | `Map<$referenceType, $reference>`; when a single call produces multiple types of reference content, they are merged into this combined output, with the key being the reference type and the value being the reference content. Streaming APIs generally do not merge output this way, while non-streaming APIs may |

### `type` Values

| Value | Description |
| --- | --- |
| `text` | Plain text |
| `markdown` | Markdown format |
| `pic` | Image address, typically used for text-to-image |
| `buttons` | Button message from orchestration, which may also include a form |
| `feedback` | Feedback, typically used in multi-Agent collaboration to report an Agent's result status for subsequent processing; see the [Agent Feedback API](/en/api-reference/agent-feedback) |
| `chart` | Visualization chart information for SQL query results |
| `table` | Result information from an SQL query |
| `result_file` | Generated file |
